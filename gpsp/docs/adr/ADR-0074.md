# ADR-0074: Defer a peer disconnect until the client's queue drains (`rfu_disc_defer`)

- **Status:** retired. Premise disproved, shipped disabled, superseded by [ADR-0076](ADR-0076.md); code removed in `4c0dcdcc` (2026-11-16). Its census (`rfu_discq`) remains.
- **Date:** unknown; first committed 2026-08-09 in `276e4450`
- **Source:** Reconstructed from code comments in `rfu.c` and `psp/main_psp.c` at `276e4450`, the handover (HANDOVER.md §4.2 at `dba5e900`) and commits `8a2a07f2`, `4c0dcdcc`.

## Decision (as made)

With `rfu_disc_defer = 1`, hold a peer's disconnect until the client's
queued host packets have been handed to the game, so the Union Room's exit
negotiation is not deleted in transit. Add `EVT rfu_discq queued= mode=`:
how many host packets were still undelivered when the disconnect arrived.

## Why (as made)

The theory was that the immediate teardown destroyed the exit handshake that
was still queued.

## Why it was retired

The instrument added alongside it read `queued=1`: one undelivered packet,
not a destroyed handshake. The handover lists it under "Falsified". ADR-0076
found the missing condition was time, not data. ADR-0076 also fixed a latent
bug here: a pending deferral was not cleared on adapter reset (harmless only
because this shipped disabled).

## Where in the code now

- `gpsp/rfu.c` — `RFU_TR_DISCQ`; the deferral itself is gone.
- `gpsp/psp/fe/link.d.inc.c` — the `rfu_discq` event. Its comment still lists modes 1 and 2 (this ADR's deferral), which can no longer occur; 0 = immediate, 3-5 = ADR-0076's grace window.
