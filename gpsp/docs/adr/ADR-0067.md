# ADR-0067: The playable build

- **Status:** current, amended twice (see ADR-0067b below and "Later amendments")
- **Date:** unknown; first committed 2026-08-09 in `276e4450`. ADR-0067b first committed 2026-09-09 in `f43e89ee`.
- **Source:** Reconstructed from the code comment "ADR-0067: THE PLAYABLE BUILD" (`psp/main_psp.c` at `276e4450`, now `psp/fe/play_defaults.h`), the handover (HANDOVER.md §3 at `dba5e900`) and commits `2b114ef1`, `0c7a9121`.

## Decision

`-DGPSP_PLAYABLE` builds a binary for someone to play, from the same source
tree as the test ("harness") build, with no run-time way to confuse the two:

- The harness control file path is pointed at a name that cannot exist
  (`.playable-no-harness/x`), so a leftover `.gpsp-harness.ini` on a player's
  Memory Stick is inert: no autopilot script, no auto-exit, no USB handoff,
  and the ROM browser comes up.
- Every harness-only key therefore returns its default, so the shipping
  values are supplied as those defaults (`PLAY_*`), not by a second code
  path. Each knob is read in exactly one place in both builds.
- Telemetry (the `EVT` event log) is compiled out and no log file is made.
- A few `config.ini` keys are forced (session rate from the trading profile
  [ADR-0071](ADR-0071.md), `core_phase = 0`, `gu_defer = 1`) so a stale user
  config cannot undo the measured configuration.

## ADR-0067b: a telemetry-free build evaluates nothing

With telemetry compiled out, `fe_evt(...)` becomes `((void)0)` and does not
evaluate its arguments (previously a stub still did the varargs work, kept
the format strings, and for example CRC'd 128 KB for a line nobody reads).
The switch is derived in the header so callers and implementation agree.

## Why

A stale control file had silently started a wireless session during a solo
benchmark (the incident behind ADR-0036). A player build must not depend on
the user having cleaned their card. The original attempt put the telemetry
switch in `main_psp.c`, which `fe_evt.c` never saw, so the "telemetry-free"
build linked the whole logger while every token check passed; only a symbol
check on the object caught it.

## Where in the code now

- `gpsp/psp/fe/paths.inc.c` — the impossible path (when `GPSP_PERF_RIG` is not set).
- `gpsp/psp/fe/play_defaults.h` — the `PLAY_*` values; `gpsp/psp/fe/boot.inc.c` — the forced keys.
- `gpsp/frontend-common/fe_evt.h`, `gpsp/frontend-common/fe_evt.c` — ADR-0067b.
- `gpsp/psp/fe/fe_priv.h` — `HARNESS_FOLD`; `gpsp/tools/build.sh` — release audit requires `.playable-no-harness`; `gpsp/psp/Makefile` — refuses a build without `-DGPSP_PLAYABLE`.

## Later amendments

- Every build profile now sets `GPSP_PLAYABLE`; test builds add `GPSP_PERF_RIG`, which reads the harness file again (`docs/BUILD-PROFILES.md`).
- `2b114ef1` (2026-11-17): in player builds each harness read now compiles to its default instead of calling the reader on the impossible path.
- `0c7a9121` (2026-11-17): telemetry bookkeeping (`TEL()`) runs in every build so per-frame code matches the test builds; `fe_evt` itself is still compiled out of player builds.

## The ADR-0036 / ADR-0067 naming discrepancy

The rename of the control file from `autopilot.ini` to `.gpsp-harness.ini`
is **ADR-0036 (mainline)** in `../DECISIONS.md`, accepted 2026-08-02. The
code written with ADR-0067 kept the two apart: at `276e4450` the
"legacy `autopilot.ini` ignored" message cites ADR-0036, and the impossible
path cites ADR-0067; current code still does (`psp/fe/boot.inc.c`).

Later text calls the rename "the ADR-0067 rename": commit `d2857c1f`,
`tools/e2e/run_video_regress.sh`, `docs/SUBSYSTEMS.md`,
`docs/CURRENT-STATE.md` and `tools/e2e/goldens/video_emerald.PROVENANCE.md`.
That is a misattribution. The date window the provenance file gives for the
broken video oracle starts 2026-08-02, ADR-0036's date, a week before
ADR-0067 existed. Correct reading: ADR-0036 renamed the channel; ADR-0067
made it unreachable in player builds. Those citations should say ADR-0036.
They are recorded here, not edited.
