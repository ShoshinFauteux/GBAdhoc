# ADR-0076: A grace window for the Union Room exit race (`rfu_disc_grace`)

- **Status:** current (120 frames in player builds, `PLAY_RFU_DISC_GRACE`)
- **Date:** 2026-08-09 (commit `8a2a07f2`); player default set after live hardware on 2026-08-10
- **Source:** Reconstructed from the commit message of `8a2a07f2`, the comment above `rfu_disc_grace` in `rfu.c`, and the comment above `PLAY_RFU_DISC_GRACE` in `psp/fe/play_defaults.h`.

## Decision

After the peer's disconnect arrives, keep the emulated adapter in CLIENT
state for `rfu_disc_grace` frames. Queued data keeps being served. If the
game issues its own disconnect inside the window, the pending teardown is
cancelled and the clean path is taken (`rfu_discq mode=5`, "race won"). On
expiry the old immediate behaviour runs (`mode=4`). An adapter reset clears
any pending teardown.

## Why

The "press A to return to lobby" error on a healthy exit is a race the slow
client loses. The pokeemerald decompilation names each step: the client
receives the disconnect as link data, a clock-master change completes, and
only then does the client issue its own disconnect, which raises no error.
If our adapter went idle first, the next wait answered "peer disconnected"
and the game set a connection error unconditionally. It appeared in 10 of
88 join logs and 0 of 88 host logs. [ADR-0074](ADR-0074.md) had deferred on
the wrong condition (data); the missing condition was time.

## Measured (from `play_defaults.h`)

On live hardware, the exit assist ([ADR-0079](ADR-0079.md)) alone still left
the join at `mode=4` with one error screen. 60 frames drained undelivered
exit packets from 64 to 3 but expired 3 short; 120 reached `mode=5` with zero
error screens on both consoles. Safe because the exit assist stops the
game's 61-frame keepalive watchdog from firing during the longer window.
