# ADR-0057: Abort a run without a hard reset, and keep the console awake

- **Status:** current
- **Date:** unknown; first committed 2026-08-09 in `276e4450`
- **Source:** Reconstructed from code comments in `psp/fe/loop.inc.c`, `psp/ctl_map.h`, `psp/ui_psp.c` and the handover summary (HANDOVER.md §4.4 at `dba5e900`, which lists it as still load-bearing).

## Decision

1. Holding START+SELECT (about 1.5 s, 90 frames) ends the run through the
   normal teardown: save data flushed, log closed, handoff offered. It is the
   same gesture that leaves the parked handoff loop
   ([ADR-0056](ADR-0056.md)), so there is one "stop whatever you are doing"
   gesture.
2. Reset the system idle timer (`scePowerTick`) about once a second for the
   whole run, not only while a network session is up.

## Why

1. The HOME dialog was not reliably reachable while the emulator drove the
   display and a script owned the pad, so in practice a run could only be
   stopped by holding POWER. Hard-resetting mid-run is how a Memory Stick
   gets a corrupt file system, which had already happened twice.
2. Scripted input goes to the emulator, not to the PSP's controller driver,
   so the system saw an untouched console and dimmed, then suspended it,
   ending unattended runs.

## Where in the code now

- `gpsp/psp/fe/loop.inc.c` — the abort and the power tick.
- `gpsp/psp/ctl_map.h`, `gpsp/psp/ui_psp.c` — the fixed 1.5 s gesture.
- `gpsp/docs/CONTROL-REMAP.md` — documents it as active in release builds, in both menu modes.

## Notes

The code records that `PSP_POWER_TICK_ALL` did not stop backlight dimming on
the custom firmware tested, so both tick types are sent explicitly.
