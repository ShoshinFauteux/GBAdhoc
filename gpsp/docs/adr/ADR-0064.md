# ADR-0064: Count how often the emulation thread is preempted (`preempt_prof`)

- **Status:** retired, removed from code in `4c0dcdcc` (2026-11-16); its question was answered
- **Date:** unknown; first committed 2026-08-09 in `276e4450`
- **Source:** Reconstructed from the code comment in `psp/main_psp.c` at `276e4450`, the handover (HANDOVER.md §4.2 and §6 at `dba5e900`) and the removal commit `4c0dcdcc`.

## Decision

A test-build census (`preempt_prof = 1`, default off) that read the kernel's
own per-thread preemption counters at four points in each frame (before the
core, the core, after the core, the vblank wait) and reported thread and
interrupt preemptions per region, with a histogram and the instrument's own
cost.

## Why

An earlier finding had attributed 3.5-4.0 ms of extra join frame time under
`emu_prio` ([ADR-0062](ADR-0062.md)) to "pure preemption overhead", inferred
from a difference of two means. Designs that followed (including
[ADR-0065](ADR-0065.md)) depended on whether the thread was interrupted twice
per frame or fifty times, so it was counted before anything was designed.

## Result

Per the handover: 2.0 preemptions per frame, every one by the project's own
transmit thread at priority 0x1F; the Wi-Fi driver never preempted the
emulation thread as a thread. That falsified the premise of ADR-0065.

## Where in the code now

Nothing. `g_emu_thid` (the emulation thread ID it used) remains for
`emu_prio` and the stall watchdog (`gpsp/psp/fe/link.b.inc.c`).
