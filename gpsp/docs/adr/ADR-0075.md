# ADR-0075: Admit at most N adapter deliveries per emulated frame (`rfu_frame_pace`)

- **Status:** retired. Shipped on in player builds, then made redundant by scheduled adapter ticks and removed in `c4243995` (2026-11-16). Sub-record ADR-0075b was removed in the same commit.
- **Date:** 2026-08-09 (commit `ca273345`)
- **Source:** Reconstructed from the commit messages of `ca273345`, `58249757`, `c4243995` and the handover (HANDOVER.md §0 at `00115404`).

## Decision

Let the client hand the game at most `rfu_frame_pace` non-empty data reads
per emulated frame (1 was the setting used), gated identically in the
`RFU_CMD_RECV_DATA` reply and in `rfu_data_avail()`. An over-budget packet
simply stays invisible until the next frame; nothing is dropped.

## Why

Hardware logs showed host packets arriving in clumps at the client, and a
probe showed the game reading the correct button and discarding it. Each
extra delivery in one frame is one extra game callback between two
main-loop passes: it grows the game's receive queue (the "Gate B" limit of
4, [ADR-0072](ADR-0072.md)) and sets up the send-queue condition under which
Emerald nulls the client's held keys ("Gate A", threshold 1). The earlier
`rfu_rx_cap` (ADR-0042) withheld packets in one place while announcing them
in the other, which caused a re-poll spin; consistent gating avoids that.
One delivery per frame is also the real radio's cadence.

Shipped on in player builds in `58249757` as the "input-eating fix, Gate A
closed".

## ADR-0075b

`rfu_pace_max_hold` (a `config.ini` key, added in the 2.0 release
`f43e89ee`): how many frames of host data the paced client may hold before
the oldest is discarded. Because arrival and delivery were both one per
frame, any queue depth was a fixed point, so this cap set the standing
latency.

## Why it was retired

`c4243995`: with scheduled ticks (D >= 1) the ticks configuration already
set frame pace and max hold to 0, so the code never ran. A full receive
queue now does the historical discard.

## Where in the code now

Nothing of the gate. `gpsp/rfu.c` keeps `rfu_rx_delivered` and the
game-queue model, with notes where the events (19, 22, 23) were removed.
Old config fixtures (`gpsp/tools/tests/fixtures/config-3.0.0.ini`) still
mention it.
