# ADR-0071: Trading profiles, applied by relaunching the app

- **Status:** partly current. The `profile` key, its rates and the relaunch flow remain; the settings row was replaced by v1.0.0 (`dba5e900`), and the speed profile's 57.00 rate is overridden by scheduled ticks ([ADR-0073](ADR-0073.md)).
- **Date:** unknown; first committed 2026-08-09 in `276e4450`
- **Source:** Reconstructed from code comments in `psp/config_psp.h`, `psp/fe/boot.inc.c`, `psp/ui_psp.c` (at HEAD and at `dba5e900`) and the handover (HANDOVER.md §3 at `dba5e900`).

## Decision

A player-owned setting `profile` in `config.ini`: 0 = speed (session rate
57.00 fps), 1 = compatibility (29.97 fps). The rate is latched once at boot
before the pacer and the timeout scaling read it, so changing the profile
saves the config and relaunches the app (from the end of normal teardown,
after save data is flushed, never from inside the UI). The playable build
also defaults to an upscaled picture; the harness stays at 1x so its timings
remain comparable.

## Why

Two consoles that disagree about how long a frame is are what gen-3 Pokemon's
wireless link cannot survive: it counts link timeouts in frames. Changing
the rate mid-session would leave the pair disagreeing. Relaunching from
inside the UI, with the I/O thread still holding the save file, is how a
save gets truncated.

## Where in the code now

- `gpsp/psp/config_psp.h` — `PCFG_PROFILE_*`, `PCFG_PROFILE_FPS_X100` (5700 / 2997).
- `gpsp/psp/config_psp.c` — the `profile` key and the scale default.
- `gpsp/psp/fe/boot.inc.c` — the latch; `gpsp/psp/fe/loop.inc.c`, `gpsp/psp/fe/teardown.inc.c`, `gpsp/psp/fe/inproc.b.inc.c`, `gpsp/psp/main_psp.c` — the relaunch.
- `gpsp/psp/ui_psp.c`, `gpsp/psp/ui_psp.h` — `UI_ACT_RELAUNCH`.

## Notes

- At `dba5e900` a UI comment says the row was replaced by a Media Engine
  mode row until, in its words, the ADR-0075 frame-pace fix made the native
  rate the only rate worth shipping; that row was itself removed on 2026-09-08. At HEAD no
  settings row writes `profile` (it is a `config.ini` key only), and a
  comment in `ui_psp.c` confirms nothing sets `g_profile_changed`: the
  relaunch mechanism is kept for the next setting that needs a reboot.
- The `profile` comment in `config_psp.h` says speed = 59.73 fps, which
  contradicts `PCFG_PROFILE_FPS_X100` (5700) a few lines above it.
