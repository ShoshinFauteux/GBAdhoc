# ADR-0056: At the end of a test batch the console parks; it does not exit

- **Status:** current (test builds only)
- **Date:** unknown; first committed 2026-08-09 in `276e4450`
- **Source:** Reconstructed from the code comment in `psp/usb_handoff.c`. No ADR text was found.

## Decision

When the unattended USB handoff loop (ADR-0053 in `../DECISIONS.md`: the
console exposes its own Memory Stick over USB between runs) runs out of
budget or receives STOP, the console stays in a "parked" state: USB keeps
being offered on a cycle and the console waits for the next command file.
Only an explicit `CMD=EXIT` leaves the loop. `handoff_park_s` bounds parking
(0 = park indefinitely).

## Why

Previously the end of a batch dropped the console to the PSP's home menu
(XMB), where it neither runs nor exports its card. Nothing the test operator
did could reach it, and a person had to press a button to start the next
batch, which defeated the loop. Parking keeps both consoles reachable;
starting the next batch is just writing a command file.

## Where in the code now

- `gpsp/psp/usb_handoff.c` — `h_park_s`, the parked loop and `PARK_WINDOW_MAX_S` (the parked window doubles while idle, up to 300 s, so the host PC is not remounting the card every 30 s).

## Notes

A parked console is escapable with START+SELECT ([ADR-0057](ADR-0057.md)).
In player builds the harness file that enables handoff cannot be read, so
handoff is always off ([ADR-0067](ADR-0067.md); `psp/usb_handoff.h`).
