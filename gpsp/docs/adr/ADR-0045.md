# ADR-0045: Put a wall clock on the flight recorder

- **Status:** current
- **Date:** 2026-08-03
- **Source:** Reconstructed from the commit message of `6ce17072` and the comments in `rfu.c` and `sdl/main_sdl.c`.

## Decision

Give every flight-recorder entry ([ADR-0043](ADR-0043.md)) a microsecond
timestamp. Read the clock once per emulated frame, never once per command,
and copy that value into each entry of the frame.

## Why

The first recorder stored only the emulated frame number. In frame numbers a
38 ms frame looks the same as a healthy 16 ms one, so a transcript could look
regular while the console was falling behind its peer in real time. Real time
is the axis the peer lives on. Saves were known to cause long frames (the
game's flash write triggers self-modifying-code detection thousands of
times), and the client died after the post-trade save.

The clock is read once per frame because the game issues about 600 adapter
commands per frame, and ADR-0021 had shown that a clock call on that path
costs milliseconds per frame.

The dump output gains `+<N>ms` per line and a closing `worst_gap_ms`. The
gate asserts the timestamps advance, because a hook that silently returned 0
would make every transcript look flawless.

## Where in the code now

- `gpsp/rfu.c` — `rfu_frame_us = gpsp_rfu_now_us()` once per frame.
- `gpsp/psp/fe/link.c.inc.c` — the PSP clock hook.
- `gpsp/sdl/main_sdl.c` — the desktop clock hook ("RFU wall clock").

## Notes

Calibration from the commit: a healthy client showed gaps up to 33 ms
between lines (one frame at 29.97 fps) while the host idled up to 505 ms
with no ill effect, so a client gap should be read against 33 ms, not zero.
