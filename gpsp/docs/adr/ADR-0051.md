# ADR-0051: Count and time the adapter's SIO work inside the core

- **Status:** current
- **Date:** unknown; between 2026-08-04 and 2026-08-09 (first committed in `276e4450`, 2026-08-09)
- **Source:** Reconstructed from code comments only (`main.h`, `serial.c`, `fe_host.c`). No commit message or handover text describes it.

## Decision

Count every `rfu_transfer()` call (one per 32-bit serial word the game
exchanges with the wireless adapter) and, at the finest profiler level
(`CORE_PHASE_FINE`), time them. Report both per frame in the `core_phase`
event as `rfux=<calls>/<us>`, plus the same pair for the single worst frame
(`wrfu`).

## Why

`rfu_transfer()` is called synchronously from the serial-register write,
which runs inside translated (JIT-compiled) guest code. Its cost was
therefore charged to the profiler's `cpu` residue, not to its `rfu` phase.
The `rfu` phase only ever measured the once-per-frame adapter tick, which is
why it read about 8 us while the adapter was doing real work. Unlike backup
memory access (thousands of calls per frame, counted only), this is one call
per serial word, so it is cheap enough to time as well as count.

## Where in the code now

- `gpsp/main.h`, `gpsp/main.c` — `cph_rfux`, `cph_rfut` and the explanation.
- `gpsp/serial.c` — the counted and timed call site.
- `gpsp/frontend-common/fe_host.c`, `gpsp/frontend-common/fe_host.h` — the `core_phase ... rfux= wrfu=` event fields.

## Notes

`core_phase` is the per-phase frame profiler from ADR-0032 (in
`../DECISIONS.md`). Its levels are set by the `core_phase` key, which is
forced to 0 in player builds ([ADR-0062](ADR-0062.md) section e,
[ADR-0067](ADR-0067.md)).
