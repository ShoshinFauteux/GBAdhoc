# ADR-0081: Make the client's lost inputs visible and countable

- **Status:** current (diagnostic tooling)
- **Date:** 2026-08-10 (commit `413989c9`)
- **Source:** Reconstructed from the commit message of `413989c9` and the headers of the fixtures and tools it added.

## Decision

Two experiments, because the adapter gate counters read clean while a
person plainly lost inputs:

1. **Arrival gap.** `arrival_gap.py` times each console's autopilot
   milestones using the log's frame-to-microsecond anchors and compares host
   with client.
2. **Identical-input drop test.** Both trade fixtures run the same open-loop
   UP/DOWN oscillation within one tile, logging the avatar's y position and
   the game's send-queue count after each press. The host is the control. A
   press that leaves y unchanged was dropped, and is tagged with the
   send-queue depth that caused it. `drop_test.py` reads it.

## Why

The commit reports that on an existing campaign the client reached two
milestones +2.06 s and +4.42 s later than the host (n about 23): input loss
was real, cost seconds, and sat on the send-queue side ("Gate A"), which the
receive-side frame pace ([ADR-0075](ADR-0075.md)) does not touch.
