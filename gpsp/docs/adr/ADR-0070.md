# ADR-0070: Wireless activates when the game starts a session, not when it logs in

- **Status:** current
- **Date:** unknown; first committed 2026-08-09 in `276e4450`
- **Source:** Reconstructed from code comments in `rfu.c` and the handover (HANDOVER.md §4.3 at `dba5e900`).

## Decision

Fire `gpsp_rfu_activated_hook()` (which brings the PSP's Wi-Fi up for the
"silent wireless" variant builds) when the game issues `RFU_CMD_BCRD_START`
(start searching for hosts) or `RFU_CMD_HOST_START` (start hosting), instead
of when the adapter login handshake completes.

## Why

ADR-0013 (in `../DECISIONS.md`) assumed adapter login meant "the player used
a wireless feature". Measured on hardware, it does not: Emerald probes the
adapter during boot (first login at emulated frame 3) and logs in about ten
more times per session as it resets the device. Login only means "an
adapter is present", which is how the game decides to show its wireless
title screen.

Firing at login brought the radio up at boot, which broke automatic role
selection: the join-first window is 240 + 0..119 frames, so two consoles
started even ten seconds apart never overlapped, both became hosts, and
neither saw the other.

## Where in the code now

- `gpsp/rfu.c` — the hook calls in `RFU_CMD_BCRD_START` and `RFU_CMD_HOST_START`, and the explanatory comment where the login hook used to fire.

## Notes

The handover recorded this fix as untested on hardware at the time
(2026-08-09). No later hardware record was found in the repo.
