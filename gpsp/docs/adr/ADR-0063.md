# ADR-0063: Log the shape of the frame-time distribution (`frame_hist`)

- **Status:** current
- **Date:** unknown; first committed 2026-08-09 in `276e4450`
- **Source:** Reconstructed from the code comment in `psp/fe/pacing.b.inc.c`. No ADR text was found.

## Decision

Emit `EVT frame_hist` once per window: an 11-bucket histogram of per-frame
work time, the current frame budget, how many frames exceeded it (`ovb`), the
window's worst frame, and three pacing counters: `late` (the frame reached
the pacing wait already past its target vblank), `forgive` (the
[ADR-0047](ADR-0047.md) arrears were written off) and `nudge` (the audio
buffer's high-water rule added a whole extra vblank).

## Why

Existing statistics gave a window mean and an all-time maximum. Failure at
45-59.73 fps was probabilistic, so the deciding quantity was how often a
frame overran, which a mean plus a max cannot show: one 42 ms frame and fifty
of them look the same. The audio-ring nudge had never been observable at all.

It reuses the work time the loop already measures, so it adds no clock
read; per frame it is at most 11 compares and an increment. Bucket edges
straddle both budgets in use (16740 us at 59.73 fps, 33400 us at 29.97).

## Where in the code now

- `gpsp/psp/fe/pacing.b.inc.c` — buckets, counters, `frame_hist_note()` and the event.
- `gpsp/psp/fe/loop.inc.c` — the feed and the `late`/`nudge` counting.
- `gpsp/psp/fe/harness.d.inc.c` — the per-window emit.
