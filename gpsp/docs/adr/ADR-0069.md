# ADR-0069: Screenshots by button chord, not by polling the Memory Stick

- **Status:** current (the chord); its contingency yield (`sched_yield_us`) was never needed and was removed in `4c0dcdcc` (2026-11-16)
- **Date:** unknown; first committed 2026-08-09 in `276e4450`
- **Source:** Reconstructed from code comments in `psp/fe/loop.inc.c`, `psp/fe/link.b.inc.c`, `psp/main_psp.c` at `276e4450`, and the handover summary (HANDOVER.md §4.4 at `dba5e900`).

## Decision

1. L+R+SELECT, on the press edge, requests a screenshot. The pad is already
   read every frame, so this is free. The shot is taken at the normal dump
   site, so it captures a finished frame.
2. The marker-file poll of [ADR-0066](ADR-0066.md) defaults to 0 (off).
3. Contingency: `sched_yield_us` / `sched_yield_frames` could reintroduce,
   deliberately and at a chosen size, the CPU yield the old file lookup had
   given the Wi-Fi threads by accident. Default off.

## Why

The marker-file lookup was a 12.4 ms blocking `sceIoGetstat` once a second on
the emulation thread, inside the timed frame, to serve a request a person
makes perhaps twice a session. The chord cannot collide with START+SELECT
(abort, [ADR-0057](ADR-0057.md)), the only other reserved gesture at the time.
