# ADR-0061: Measure the gap between transport pumps

- **Status:** current
- **Date:** unknown; first committed 2026-08-09 in `276e4450`
- **Source:** Reconstructed from code comments in `netdrv/netdrv.h`, `netdrv/netdrv.c` and `frontend-common/netpacket_host.c`. No ADR text was found.

## Decision

Record the time between successive calls of the network transport's pump
(`netdrv_pump`), as a maximum and a mean, and report it in the transport
statistics line.

## Why

At 59.73 fps the host measured a smoothed round-trip time of 36 ms and a
retransmission timeout of 200 ms, yet retransmitted packets were on average
3063 ms old (max 10443 ms) when resent: 15x later than the timeout (numbers
from the code comment). Two explanations predict that: the retransmit scan
not running often enough (the pump runs once per emulated frame, so a long
frame is a long gap), or the scan running fine while the send window is
blocked behind its oldest packet. Gaps of seconds mean the first; gaps of
about 16 ms with packets still aging mean the second.

## Where in the code now

- `gpsp/netdrv/netdrv.h` — `pump_gap_max_us`, `pump_gap_sum_ms`, `pump_gap_n` and the explanation.
- `gpsp/netdrv/netdrv.c` — `last_pump_us` and the interval measurement.
- `gpsp/frontend-common/netpacket_host.c` — the reported mean/max.
