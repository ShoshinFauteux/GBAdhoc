# ADR-0052: The flight recorder dumps on any transition that ends a live session

- **Status:** current
- **Date:** unknown; between 2026-08-04 and 2026-08-09 (first committed in `276e4450`, 2026-08-09)
- **Source:** Reconstructed from the code comment above `RFU_SET_STATE` in `rfu.c`. No commit message or handover text describes it.

## Decision

Dump the [ADR-0043](ADR-0043.md) flight recorder whenever the emulated
wireless adapter leaves a live state (`CLIENT` or `HOST`) because of a reset,
a local disconnect (`DISC_LOCAL`) or a peer disconnect (`DISC_PEER`), not only
on reset.

## Why

The client's graceful exit path is CLIENT, then idle via DISC_PEER, then idle
via RESET. By the time RESET fired, the state was already idle, so the
recorder stayed silent on exactly the console and transition under study;
only the fatal path was ever captured. Disconnects from a live state also end
a session, and the order of events between the two consoles at that moment
was the open question: the client starts the exit, yet the host was seen
sending `RFU_CMD_DISCONNECT` (0x30) first.

## Where in the code now

- `gpsp/rfu.c` — `RFU_SET_STATE` and the comment above it.

## Notes

The same change made three previously silent state transitions report
themselves with a cause. The comment also records a build trap: inside a
multi-line `do {} while (0)` macro, a comment line without a trailing
backslash ends the definition early, and the resulting errors appeared about
200 lines away from the cause.
