# ADR-0047: Pace against the vblank counter, not by counting waits

- **Status:** current
- **Date:** 2026-08-04
- **Source:** Reconstructed from the commit message of `5434cc09` and the comments in `loop.inc.c` / `pacing.b.inc.c`. DECISIONS.md (after ADR-0048) notes this as the session's most consequential change with no entry.

## Decision

Pace frames against an absolute target on the display's vblank counter
(`sceDisplayGetVcount()`), so a frame that overran consumes its own budget.
If the console falls more than `PACE_VC_RESYNC_VB` (8) vblanks behind, the
debt is forgiven rather than repaid.

## Why

`sceDisplayWaitVblankStart()` waits for the next vblank edge. The old code
called it once plus once per extra vblank, so any frame whose work had
already crossed an edge waited for the edge after the intended one. The
period silently became `ceil(work / 16.74 ms) + extra` instead of
`1 + extra`. That explained why the joining console sat at 19.98 fps with
10-15 ms of slack against a 33.4 ms budget, and why lowering the clamp never
closed the host/client gap.

Rig result stated in the commit (prediction written before the run): with
12 ms of injected work on the join, the join went from 19.97-20.37 fps and a
failed scenario to 29.96-29.97 fps and a pass. Unchanged at 0 injected work.

Paying back arrears by sprinting was judged worse than being late.

## Where in the code now

- `gpsp/psp/fe/pacing.b.inc.c` — `g_vc_target`, `PACE_VC_RESYNC_VB`, and the `forgive` counter in the frame-time histogram ([ADR-0063](ADR-0063.md)).
- `gpsp/psp/fe/loop.inc.c` — the pacing wait.
- `gpsp/tools/e2e/run_exit_room_test.sh` — `--slow-join`, the injected-work option used to prove it.

## Notes

Scope stated in the commit: this fixed the host/client rate disparity and
made fast-forward proportionally faster. It did not fix the Union Room exit
crash; the rig exited cleanly while a full vblank behind.
