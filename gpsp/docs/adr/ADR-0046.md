# ADR-0046: Log the input mask the core actually receives

- **Status:** current
- **Date:** 2026-08-03
- **Source:** Reconstructed from the commit message of `b0729933` and the comments in `fe_host.c` / `loop.inc.c`.

## Decision

Log one event line each time the button mask handed to the emulated GBA
changes. Read it from `fe_host_input_mask()`, which is exactly what the core's
`input_state()` returns (pad input OR harness-injected input), not from the
PSP pad directly.

## Why

The joining console lost most movement input in the Union Room, in every
build. Reading the code suggested the input path was sound, but the log had
never recorded input at all. A press-and-release log separates two opposite
causes: a mask held for many frames while the character does not move means
the game declined it (a link-side problem); a flickering or missing mask
means the emulator lost it.

Two corrections went in with it. The probe first read the PSP pad, which the
test harness never uses, so it could not be tested; it now reads the
combined mask. The gate first passed on a single priming line; it now
requires at least 10 non-zero masks.

## Where in the code now

- `gpsp/frontend-common/fe_host.c`, `gpsp/frontend-common/fe_host.h` — `fe_host_input_mask()`.
- `gpsp/psp/fe/loop.inc.c` — the logged-on-change event.

## Notes

exists, rather than that it is correct, passed three times that day without
exercising its subject. Later investigation of the input loss continued in
